ViewModel

ViewModel — это компонент архитектуры Android, предназначенный для хранения и управления данными, связанных с пользовательским интерфейсом, учитывая его жизненный цикл. В отличие от обычных классов, ViewModel сохраняет свое состояние при повороте экрана или других конфигурационных изменениях. Это позволяет приложениям более эффективно управлять данными, обеспечивая их доступность, пока Activity или Fragment активно. Благодаря viewModelScope можно запускать корутины, которые автоматически отменяются, когда ViewModel уничтожается, предотвращая утечки памяти.

class MyViewModel: ViewModel() {
    
    val message = MutableLiveData<String>()

    fun loadMessage() = viewModelScope.launch {
        message.value = "Данные загружены"
    }

    override fun onCleared() {
        super.onCleared()
        // Освобождение ресурсов
    }
}
onCleared

Вызывается перед уничтожением экземпляра ViewModel. Предназначен для освобождения ресурсов, таких как отмена корутин, очистка подписок или освобождение памяти. Переопределение этого метода позволяет разработчикам управлять логикой, необходимой для безопасного завершения работы ViewModel.

override fun onCleared() {
    super.onCleared()
    // Отменяем корутину при уничтожении ViewModel
    job?.cancel()
}
AndroidViewModel

Подкласс ViewModel, который предоставляет доступ к Application. Полезен для работы с глобальными ресурсами приложения, такими как базы данных или общие настройки, и предотвращает утечки памяти, поскольку связан с жизненным циклом приложения, а не конкретного компонента UI.

class MyAndroidViewModel(
    application: Application
): AndroidViewModel(application) {
    
    private val context: Context = application.applicationContext
}
Assisted

Позволяет передавать динамические данные в ViewModel.

@HiltViewModel(assistedFactory = MyViewModel.Factory::class)
class MyViewModel @AssistedInject constructor(
		@Assisted val userId: Int,
		savedStateHandle: SavedStateHandle
): ViewModel() {
		
		@AssistedFactory
		interface Factory {
				fun create(userId: Int): MyViewModel
		}
}

@Composable
fun MyScreen(
		userId: Int,
		viewModel: MyViewModel = hiltViewModel(
				creationCallback = { factory: MyViewModel.Factory -> factory.create(userId) }
		)
) {}
ViewModelStore

Контейнер для хранения ViewModel. Он управляет их жизненным циклом, гарантируя, что ViewModel сохраняются, пока их владелец (обычно Activity или Fragment) жив.

• Внутри - mutableMapOf<String, ViewModel> где ключ - идентификатор модели.

ViewModelStoreOwner

Интерфейс который обеспечивает доступ к ViewModelStore.

ViewModelProvider

Класс, который управляет созданием и предоставлением экземпляров ViewModel. Он обеспечивает хранение ViewModel при изменениях конфигурации (например, при повороте экрана) и повторное использование существующего экземпляра.

ViewModelProvider.Factory

Интерфейс, который используется для кастомного создания экземпляров ViewModel. Его применяют, когда ViewModel требует зависимости, передаваемые через конструктор.

Lifecycle

Когда мы запрашиваем ViewModel - ViewModelProvider проверяет существует ли такая модель. Если найдена - возвращается экземпляр. Если не найдена - ViewModelProvider.Factory используется для создания новой ViewModel и она потом сохраняется в ViewModelStore. Созданная ViewModel жива пока жив экран. Когда экран уничтожается - ViewModelStore очищается и все хранящиеся в нем ViewModel удаляются. Для каждой ViewModel вызывается onCleared .

SavedStateHandle

Key-value мапа. Передается в конструктор вьюмодели. Позволяет записывать и извлекать объекты из сохраненного состояния.

@HiltViewModel
class MyViewModel @Inject constructor(
    savedStateHandle: SavedStateHandle
): ViewModel() {
		private val id: Int? = savedStateHandle.get<Int>("id")
		private val idStateFlow: StateFlow<Int> = savedStateHandle.getStateFlow("id", 0)
		
		init {
				savedStateHandle["id"] = 1
        savedStateHandle.remove<Int>("id")
    }
}
Вопросы на собесе (11)
  1. Что такое ViewModel и какова его роль в архитектуре Android?

    ViewModel — это класс, который хранит и управляет UI-ориентированными данными в Android-приложениях. Он отделяет бизнес-логику от UI, переживает изменения конфигурации и сохраняет данные, что улучшает пользовательский опыт и упрощает тестирование.

  1. Зачем использовать Jetpack ViewModel, а не создавать свой собственный класс?

    Jetpack ViewModel управляет данными при изменении конфигурации, таких как поворот экрана, и сохраняет их в течение жизненного цикла активности или фрагмента. Создание собственного класса не решает эту задачу автоматически и требует дополнительной работы для управления состоянием и жизненным циклом.

  1. Как ViewModel взаимодействует с жизненным циклом Activity или Fragment?

    ViewModel взаимодействует с жизненным циклом Activity и Fragment, переживая изменения конфигурации и сохраняя данные. Он отделяет бизнес-логику от UI и эффективно управляет состоянием приложения.

  1. Для чего нужен класс SavedStateHandle в ViewModel?

    Класс для сохранения состояния в ViewModel, позволяющий сохранять данные при изменении конфигурации.

  1. Как ViewModel переживает пересоздание Activity?

    ViewModel сохраняется в ViewModelStore, и новая Activity получает доступ к той же ViewModel, избегая ее пересоздания.

  1. Где хранится ViewModel?

    В HashMap внутри ViewModelStore.

  1. Где хранится ViewModelStore?

    В ActivityThread.

  1. Как разделять ViewModel между несколькими Fragment в одной Activity?

    Чтобы разделить ViewModel между несколькими Fragment в одной Activity, создайте ViewModel в Activity и используйте activityViewModels() в Fragment. Это обеспечит доступ всех Fragment к одному экземпляру ViewModel, позволяя им делиться данными.

  1. Жизненный цикл ViewModel?

    • Создание: ViewModel создается при запросе через ViewModelProvider и сохраняется при изменениях конфигурации.

    • Использование: ViewModel активен, пока связанный Activity или Fragment существует и может быть видимым.

    • Очистка: При окончательном уничтожении Activity или Fragment вызывается onCleared(), где освобождаются ресурсы.

  1. Когда вызывается метод onCleared?

    Метод onCleared() вызывается, когда ViewModel больше не привязан к Activity или Fragment, то есть при их окончательном уничтожении. Это происходит, когда все ссылки на ViewModel удаляются, и ViewModel освобождает ресурсы, такие как подписки на потоковые данные или операции с базами данных.

  1. Как работает viewModelScope?

    viewModelScope связан с жизненным циклом ViewModel. Когда корутины запускаются в viewModelScope, они автоматически отменяются при уничтожении ViewModel, что предотвращает утечки памяти и обеспечивает корректное завершение задач. По умолчанию, viewModelScope работает с диспетчером Dispatchers.Main.immediate, что позволяет выполнять задачи в основном потоке, но может переключаться на другие диспетчеры для фоновых задач.
